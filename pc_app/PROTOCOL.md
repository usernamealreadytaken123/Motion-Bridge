# Android → ПК: UDP JSON v2

Одна UTF-8 JSON-дейтаграмма = один snapshot. Частота отправки: 50 Гц.
Старые верхнеуровневые поля сохранены. Неизвестные поля расширений игнорируются
при интерпретации и остаются в записи. Протокол без `protocol_version` считается v1.
Неизвестная версия, тип пакета, повторяющиеся ключи, неконечные числа и неверные
типы данных отвергаются. Монотонные timestamps и sequence — целые int64 >= 0.

| Поле | Значение |
|---|---|
| `protocol_version` | `2` |
| `packet_type` | `telemetry` |
| `session_id` | Новый UUID на каждый старт UDP; не является аппаратным ID |
| `sequence` | Номер дейтаграммы внутри сессии, начинается с 0 |
| `timestamp` | Unix time телефона, секунды; для календаря, не для вычисления Δt |
| `device_timestamp_ns` | `elapsedRealtimeNanos()` перед отправкой |
| `sensor_timestamps_ns` | Исходное время последнего события каждого сенсора; 0 — ещё нет измерения |
| `quaternion` | Android rotation-vector quaternion `{w,x,y,z}`, без визуального центрирования UI |
| `gyroscope` | Последнее событие гироскопа, `{x,y,z}`, рад/с, оси Android-устройства |
| `linear_acceleration` | Android `TYPE_LINEAR_ACCELERATION`, м/с²; это не сырой акселерометр |
| `height_above_surface_m` | Прежнее поле фиксированной высоты из TrackingConfiguration |
| `planar_odometry` | `null`, если одометрия ещё не создавалась; иначе блок ниже |

Внутри `sensor_timestamps_ns`: `quaternion`, `gyroscope`, `linear_acceleration`.
Эти три измерения обычно имеют разные времена. Пакет является snapshot, а не
синхронным IMU-сэмплом. Сырые измерения, включая гравитацию, потребуются на этапе VIO.

| Поле `planar_odometry` | Значение |
|---|---|
| `epoch` | Увеличивается при старте/сбросе позиции; новая система отсчёта |
| `timestamp_ns` | Timestamp обработанного кадра камеры, 0 до первого кадра |
| `status` | STOPPED, STARTING_CAMERA, INITIALIZING, TRACKING, DEGRADED, LOST, ERROR |
| `camera_active` | Состояние камеры по контроллеру |
| `x_m`, `y_m` | Абсолютная накопленная 2D-позиция, метры |
| `heading_rad` | Накопленный поворот в плоскости, радианы |
| `delta_x_m`, `delta_y_m` | Изменение на обработанном кадре; не суммировать повторные timestamps |
| `surface_distance_m` | Расстояние, реально использованное камерным алгоритмом |
| `tracked_points`, `inliers` | Число соответствий и принятых точек |
| `inlier_ratio` | Доля от 0 до 1; не вероятностная оценка точности позиции |
| `image_scale` | Относительный масштаб между кадрами |
| `intrinsics_approximate` | Параметры камеры приблизительные по текущему контроллеру |

Ключ траектории: `(sender, session_id, epoch)`. Идентификатор кадра в пределах
траектории — `timestamp_ns`. Сброс или повторный старт одометрии разрывает траекторию.
При STOPPED/DEGRADED/ERROR координаты могут быть последним сохранённым результатом.
Последовательность новых UDP-пакетов не означает последовательность новых кадров.

2D-координаты заданы в плоскости кадра при сбросе: начальный X направлен вправо,
Y — вниз в ориентированном изображении. Они не совпадают автоматически с мировой
системой rotation vector или осями будущей 3D-сцены. Z не измеряется этим алгоритмом.

Timestamp камеры не объявляется синхронизированным с IMU: для этого ещё предстоит
проверить источник времени камеры и откалибровать offset. Часы ПК и Android также
не синхронизированы. Нельзя вычитать их монотонные времена или заявлять сетевую
задержку по разнице календарных часов.

## Запись JSONL

Один файл — один запуск ПК-приёмника. Каждая строка содержит:

- `record_version: 1`;
- `pc_receive_monotonic_ns` и `pc_receive_unix_ns`;
- `sender: [IPv4, port]`;
- `raw_base64`: точные байты дейтаграммы, включая повреждённые;
- `payload`: разобранный объект либо null;
- `error`: причина отказа либо null;
- `sequence_result`: new / reordered / duplicate / too_late для корректных пакетов.

Запись идёт в отдельном потоке с ограниченной очередью. Переполнение или ошибка
диска завершают приём с ошибкой, чтобы не выдавать неполную запись за полную.
Размер UDP ограничен 65507 байт; обычный v2 пакет укладывается в 1400 байт
(проверяется на общем образце). Кадры и массивы кейпоинтов сюда не включаются.
