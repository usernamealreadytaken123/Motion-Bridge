# Motion Viewer: 3D, replay и Windows-сборка

## Быстрый запуск

Дважды щёлкните `pc_app/dist/MotionViewer.exe`. Сборка включает Python, Qt и NumPy;
устанавливать их отдельно не нужно. При запуске встроенные библиотеки распаковываются
во временную папку, поэтому старт может занять несколько секунд. Сборка Windows x64,
не подписана цифровой подписью; политики Windows могут ограничивать запуск.
Права администратора не требуются, настройки firewall автоматически не меняются.

Для живого режима оставьте `0.0.0.0:5005`, нажмите «Начать приём», на Android
укажите IPv4 компьютера и включите UDP. Для воспроизведения остановите приём
и нажмите «Открыть JSONL…». Новый APK для этих функций не нужен: протокол не менялся.
Ни при открытии записи, ни при запуске приложения UDP автоматически не включается.

## 3D-модель

На вкладке «3D-ориентация» находится объёмная модель телефона с экраном и обозначением
верхнего края. Центр неподвижен. «2D-траектория» — отдельная вкладка; обе обновляются
из одной выбранной сессии вместе с графиками.

- Quaternion `(w,x,y,z)` нормализуется перед отображением.
- Оси устройства в естественной ориентации: +X вправо, +Y к верхнему краю, +Z из экрана.
- Quaternion переводит оси устройства в правый мировой базис East / магнитный North / Up.
  Оси плоской одометрии сюда не подмешиваются.
- «Текущий поворот → ноль» задаёт визуальную базу: `R_display = R_referenceᵀ R_current`.
  «Мировые оси» отменяет базу. Данные телефона и файл записи не изменяются.
- При смене отображаемого потока или открытии нового файла база сбрасывается.
  При перемотке внутри того же потока сохраняется.
- При отсутствии/устаревании quaternion отображается предупреждение.

Геометрия действительно вращается в трёх измерениях и проецируется через Qt QPainter.
Отдельный OpenGL-драйвер/PyOpenGL не нужен. Это показ ориентации, не 3D-одометрия.
Системы координат сверены с [документацией Android](https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion#sensors-motion-rotate).

## Воспроизведение

1. Остановите UDP, откройте JSONL, созданный консольным или графическим приёмником.
2. Дождитесь фоновой проверки файла. Неверные файлы отклоняются с номером строки.
3. Кнопки «Воспроизвести» / «Пауза», ползунок и скорости 0.25×, 0.5×, 1×, 2×, 4×, 8×
   управляют общей шкалой. «В начало» возвращает к началу с паузой.
4. В конце воспроизведение останавливается; следующий запуск начинает файл сначала.
5. «Закрыть запись» освобождает файл и возвращает возможность живого приёма.

Шкала использует **монотонное время приёма ПК из записи**, не текущие часы компьютера.
Сетевые паузы сохраняются; пауза плеера замораживает время всех панелей. При открытии
давней записи датчики не становятся автоматически устаревшими. Quaternion не
интегрируется из гироскопа; позиция не вычисляется из ускорения. Всё берётся из записи.

Файл читается без изменений, данные обратно по сети не отправляются. В фоне проверяются
формат, порядок времён и соответствие JSON исходным байтам UDP. Затем используется
индекс смещений, 16 байт на строку; весь файл в памяти не хранится. Ограничения:
2 000 000 строк, максимум 1 МиБ на строку, прежние лимиты отображаемой истории.
Отклонённые UDP-дейтаграммы внутри корректного JSONL допустимы и учитываются в статистике.
Склеенные записи с откатом времени и повреждённые строки отклоняются.

Перемотка назад заново восстанавливает состояние из начала файла. Обработка идёт
короткими порциями с возвратом управления окну; при длительной перемотке виден статус
подготовки. Модель, траектория и графики переходят к выбранной позиции вместе.
Не открывайте файл до завершения его записи: изменение файла после открытия останавливает replay.
«Очистить графики» изменяет только экран; после перемотки история восстанавливается из файла.

## Настройки и журнал

По умолчанию `%LOCALAPPDATA%/MotionViewer/` содержит:

- `settings.json`: адрес/порт прослушивания, папки записи и открытия файлов,
  включение записи, скорость воспроизведения и размеры окна;
- `recordings/`: новые сессии, если не выбрана другая папка;
- `logs/motion-viewer.log`: запуск и ошибки, до 2 МБ плюс 3 архивных файла.

Кнопка «Журнал приложения» открывает журнал. Измерения в него не дублируются.
Настройки записываются атомарно. Повреждённый файл сохраняется рядом как
`settings-invalid-…json`, после чего используются значения по умолчанию.
Старые записи в `pc_app/recordings/` не перемещаются; их можно открыть через диалог.

Дополнительные параметры запуска: `--open ПУТЬ.jsonl`, `--data-dir ПАПКА`.
Настройки для запуска из исходников и `.exe` общие, если не указан другой каталог.

## Сборка и проверка

Из корня проекта, с установленным Python 3.12:

```powershell
.\pc_app\.venv\Scripts\python.exe -m pip install -r pc_app/requirements-build.txt
.\pc_app\build_windows.cmd
```

Скрипт сначала запускает тесты, затем создаёт `pc_app/dist/MotionViewer.exe`
и проверяет готовую сборку через локальную тестовую сессию. Проверка запускает `.exe`
из временной рабочей папки, без Python-переменных окружения и с системным PATH.
Кэш и промежуточные файлы находятся в `pc_app/build/`. Системные DLL не заменяются.
Сборка ограничивает поиск DLL, чтобы не захватывать несовместимый ICU из посторонних
программ в PATH, и согласует версии библиотек MSVC внутри комплекта с Qt.
Механизм упаковки: [PyInstaller](https://pyinstaller.org/en/stable/usage.html).

Повторная автоматическая проверка непосредственно готового `.exe`:

```powershell
.\pc_app\.venv\Scripts\python.exe pc_app/verify_windows_build.py
```

Это скрытый диагностический режим Qt: локальный UDP, запись 40 синтетических пакетов,
replay, проверка ориентации, сохранения настроек и рендер окна. Создаёт отчёт JSON,
PNG и тестовые данные внутри `artifacts`; не использует реальный телефон.
Успех — поле `ok: true`, для автономной сборки также `frozen: true`.
Python здесь нужен только разработчику для запуска проверяющего скрипта;
пользователь запускает сам `MotionViewer.exe` без него.
Эта проверка не заменяет испытание на другом компьютере без Python и с реальным Android.

Обычные тесты:

```powershell
.\pc_app\.venv\Scripts\python.exe -m unittest discover -s pc_app/tests -v
```

Видео камеры намеренно не добавлено. Модель показывает только вращение; 3D-перемещение
и новая визуально-инерциальная одометрия остаются отдельными задачами.
